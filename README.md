# Akai Fire: Custom Firmware Project

Never came up with a snappy name for this one, but it's exactly what I wanted this device to be in the first place

**The Akai Fire is now a standalone step sequencer and includes:**

-internal clock with clock out and external sync 

-patterns, assignments, and settings saved internally to the device memory

-step sequencer with 32 tracks: 24 drum (single note and/or cc per step) and 8 melodic tracks (expands capability to 3 notes per step)

-each individual sequencer track can be of any length from 1 to 128 steps and can be changed on the fly by pressing alt+the desired last step for that row. Tracks can stretch up to 8 pages in length if needed.

-accents,probability & ratchets: hold a step, then add or adjust the likelihood that it will sound and/or whether any ratcheting occurs and how much. accents can be adjusted by pressing shift+step and cycles between strong, soft, and normal.

-32 patterns, autosaved after 3 sec as you write them. if a new pattern is selected, the change happens at the end of the bar, regardless of how many steps a given sequencer track may contain.

-song mode, where you can string the patterns together however you wish

-note mode, where the notes are laid out like the fretboard of a bass guitar

-drum mode with four 16 pad grids side-by-side, each independently assignable, and a 16 Levels mode to get around the velocity limitations of the fire

-fader mode, which reimagines the pad grid as a display of horizontal faders that can be scrolled through, each with 16-step resolution 

-host mode, where the firmware steps aside and allows an attached device dictate the layout and behavior

-generally informative context on the oled

-4 banks of the four encoder knobs for each of the main modes you're in, assignable in the menu to whatever you want them to send

-button LED/pad lighting

-send & receive MIDI over USB to anything that is capable of speaking the language

-easy installation and restore utilities included in the pack


A note here about some of the things one might find in addition:
My personal copy of this firmware gets updated pretty often at this point and some of the features I put in for myself will leak into the public release. For example, pressing the DRUM key twice now goes into MPC mode, which is a map of my MPC1000 face buttons. It's a thing specific to me that I'm leaving until/unless this gets enough outside traction to make it worth removing. Another example is ORC mode, a menu option that brings up a surface specific to the ORC project. Poke around and you will find neat things, such as all the pretty visuals in lights mode.
Some defaults in here (like displaying the line markers) may be confusing, but everything can be turned off/adjusted in the menu. 

The device will show up to other things as ORC. I should probably change this, as it has become only tangentially-related to that larger project.


**I am genuinely proud of this and I hope that other people will find this helpful in some way.**

## Installing it

Download the zip from the [latest release](https://github.com/jamisonx-dev/fire-cfw-standalone-public/releases/latest)
and unzip it. Plug the Fire in with USB and close FL Studio or any other program using it. Then:

| On | Do |
|---|---|
| **Windows** | Double-click **`Install custom firmware.bat`**. The first time, Windows asks to allow a USB driver for the Fire's update mode: click Yes. (If it says "Windows protected your PC": More info, then Run anyway.) |
| **macOS** | Install dfu-util once (`brew install dfu-util`, from [Homebrew](https://brew.sh)). Then double-click **`Install custom firmware.command`** (the first time: right-click it, Open). Put the Fire into update mode by hand when it asks (below). |
| **Linux** | Install dfu-util once (`sudo apt install dfu-util` or your distro's package). Then run `sh "Install custom firmware.command"` in the unzipped folder. It asks for your password (dfu-util needs USB access). |

Before it writes anything, it backs up the Fire's whole memory and keeps Akai's original firmware as
`backups/ORIGINAL_Akai_firmware.bin`. **Restore original Akai firmware** (`.bat` / `.command`) puts that back.
Akai's bootloader is never written, so you can always get back in: unplug the Fire, hold **STEP + NOTE + DRUM +
PERFORM**, plug it back in (the Fire stays dark: that is update mode). On Windows and Linux the installer asks a
running Fire to switch to update mode by itself; on a Mac you do the button combo when it asks.

**Upgrading from an earlier version:** run Install again. It sees your saved patterns and asks: **K** keeps them (the
new firmware loads them), **F** erases them, **C** stops. Either way they are in the backup it just made.

How each was tested for this release (2026-11-13, on the author's Fire, from this release's files):
- **Windows 10:** install keeping patterns (found the Fire by itself, as "FLAME" and as v0.29b's "ORC FW seq"); restore
  Akai's original (the chip read back byte for byte equal to the original); a fresh install on Akai's firmware (the
  firmware read back equal to the release file); restoring a backup.
- **Linux (Raspberry Pi OS):** install keeping patterns, restoring a backup, with another program using the Fire's port
  at the same time.
- **macOS: not tested** (no Mac here yet). It runs the same script as Linux; if you try it, please say how it went.
- **Upgrading v0.29b -> v0.39, keeping patterns:** a Fire holding patterns that v0.29b saved was updated to v0.29b and
  then to v0.39 with K. Read off the running Fire before and after, every step, pattern, track length and setting was
  identical (the two settings bytes v0.39 adds start at their defaults).

The scripts are in [`installer/`](installer/) if you want to read them first (plain text).

## What's new in v0.39 (since v0.29b)

- **New name: FLAME, and two USB MIDI ports.** `FLAME seq` is the sequencer (what "ORC FW seq" was); `FLAME DAW` is
  only for DAW mode. On Windows 10 they show as `FLAME` and `MIDIIN2 / MIDIOUT2 (FLAME)`.
- **DAW mode** (BROWSER > MCU/HUI/DAW): the Fire as a **Mackie Control** or **HUI** control surface for a DAW on a
  computer, no extra software: faders, mute / solo / arm / select for 8 tracks, transport, banking, the knobs as
  V-pots, track names on the screen. **Tested with REAPER (MCU). HUI has not been tried with Pro Tools or any HUI host
  yet**, and the other DAWs are untested: reports welcome.
- **PAINT mode** (BROWSER > Paint): paint the pads in 16 colours, save 4 paintings.
- **BROWSER > About**: the version, the build and the last crash on record, on one screen. A photo of it is the best
  bug report.
- **One second view per mode button:** STEP twice = track levels, NOTE twice = UNIVERSAL (a general MIDI controller
  with 8 pages, stored on the Fire), DRUM twice = the MPC remote, PERFORM twice = the DAW page (only with the ORC).
- A more detailed crash record and many fixes (USER_GUIDE).
- **Removed:** the light shows (PLASMA, SPARKLE ... and the rest), the Pi VU bars and the ORC pads page, to free
  memory for DAW mode.
- **Only with the ORC** (the author's Raspberry Pi rig): ORC mode and the DAW page. Without it they stay out of the way.

Every control: [`fw/fireseq/USER_GUIDE.md`](fw/fireseq/USER_GUIDE.md).

## Status (2026-11-13)

- **This release: v0.39** (`ORCBUILD=e22dc97f`), built from this repo's source. Since v0.29b: see "What's new".
- **Soak:** 4 hours on the author's Fire (its own sequencer playing, the author playing it by hand on and off): no crash,
  no misread, the Fire never dropped off USB; the longest single pass of its main loop was 4.0 ms.
- **Crash reports survive unplugging** (new in v0.39): the last crash is kept in flash, so BROWSER > About still shows it
  after a power-off.
- Crashes: two in hands-on use on 2026-11-11 (v0.33) were traced to one wrong bit read from the chip's own flash at
  the start of the LED interrupt. Since then the firmware counts such a misread instead of crashing on it, uses more
  flash wait states and spends less time in that interrupt; none has been seen since on the author's Fire (hours of
  hands-on play since 2026-11-12, plus the soak above).
  Why the flash returned a wrong bit is not known.

## How we got here (2026-10-05 / 06)

1. Dumped the chip through ST's update mode (button combo) and backed it up twice.
2. Looked inside: the chip (STM32F401RC), the flash layout, Akai's fonts and boot logos, the boot
   check (just an end marker, no checksum).
3. Found Akai's "reboot to update mode" SysEx (0x72): from then on, everything was done remotely.
4. Emulated Akai's firmware to map the pins and capture the screen's start-up sequence.
5. Built firmwares step by step: boomerang (boot path) -> hello (USB MIDI) -> oled (screen) ->
   probe (mapped every button, pad, knob and LED with the owner's help) -> the sequencer.

## What's in this repo (and what isn't)

This repo holds **only our own work**: `fw/` (firmware
source, test and measurement scripts) and these docs. The author's working folder also has
things that are deliberately **not** published (`.gitignore` is an allow-list):

- `fire_flash_v0.21_a.bin`, `_b.bin`, `optbytes.bin`, `otp.bin`: backups of the stock chip.
  **Akai's copyrighted code.** Also on the Pi in `~/fire_fw/`.
- `patterns_backup_v03.bin`: the pattern area before the v0.4 format change.
- `fire_fonts_and_logos.png`: the graphics stored in Akai's firmware.
- `tools/`: the emulator and analysis scripts that run Akai's firmware.

The USB stack (TinyUSB, MIT) is not vendored: see `fw/DEVELOPER.md` for fetching it.
